# Interactive Script Orchestrator

一个面向交互叙事游戏的可视化脚本编排器 Demo。

项目当前聚焦于五个核心概念：**脚本、内容项（对话与按钮）、事件、条件、表现标签**。编辑器不试图替作者自动创作剧情，而是让作者把已经设计好的对话、顺序和交互关系清楚地编排出来，并直接预览玩家实际会经历的流程。

完整更新记录见 [CHANGELOG.md](CHANGELOG.md)。

## 核心模型

### 1. 脚本是基本载体

脚本是时间线上的基本节点，也是整个编辑器的主体。作者可以：

- 在时间线上新增脚本；
- 拖动脚本改变作者规定的执行顺序；
- 自定义每段脚本的对话内容；
- 将脚本设置为只执行一次或允许复用；
- 通过事件调用其他脚本；
- 在复用脚本后返回此前流程，从而形成闭环。

这里的“时间线”不是现实时间刻度，而是作者规定的主要脚本进行顺序。运行时可以因为按钮、条件和事件进入支线，也可以调用可复用脚本后回到原流程。

### 2. 脚本承载对话

每个脚本可以包含一条或多条对话。对话通过可复用标签取得统一的表现定义。标签可以新建、搜索和重命名，并集中设置：

- 标签名称，例如叙述、父亲、环境、资料或 AI；
- 文字颜色；
- 出现动效；
- “末尾加载转圈”动效，可用于 AI 分析中等持续等待状态；
- 输出类型：普通文本、角色对话、系统提示或数据/终端；
- 当前使用该标签的对话引用位置。

每条对话只需选择标签，并继续独立设置：

- 出现前等待时间（上一条内容完成后开始计时；首条对话从进入脚本后开始计时）；
- 持续方式：持续保留、固定时长，或直到指定事件发生；
- 固定时长从文字完全出现后开始计算；事件库也可以使用“销毁对话”动作移除指定对话；
- 完全显示所需时间；
- 出现条件与产生事件。

修改标签定义后，所有引用该标签的对话会同步采用新的颜色、动效和输出表现。旧项目中的客体、颜色和动效会自动迁移为标签。

“导出游玩 HTML”会把当前项目完整内嵌为一个可离线打开的单文件游戏。玩家打开文件后会从第一个脚本自动开始，编辑器、事件记录、标签名称和输出类型的调试边框不会显示；颜色、逐字显示、标签动效、按钮和侧栏交互会保留。JSON 导入仍用于继续编辑已有工程。

运行时会分别保留说明书、聊天和 AI 等侧栏会话。S08 的派生分析结果会归入同一个 AI 会话，离开后重新打开仍可看到此前的资料与分析内容；只有停止或从头运行时才清空。说明书首次显示和再次打开时都从顶部开始阅读。

对话区只呈现角色交流和必要的现场叙述，不承担教程提示、操作提醒或系统评价。

### 3. 对话可以关联条件和事件

一条对话可以承载两个独立属性：

- **出现条件**：只有条件满足时，对话才会出现；
- **产生事件**：对话出现后触发指定事件。

例如，某句对话出现后产生“药柜按钮可用”事件，界面才显示“去药柜”按钮。玩家感受到的是剧情自然推进，而不是系统告诉玩家下一步该做什么。

### 4. 按钮附着于脚本

按钮不是独立漂浮的菜单，而是与对话同级、可在脚本内容序列中排序的交互项。按钮放在哪条对话之后，就会在运行到该位置时进入可显示状态。按钮可以设置：

- 显示文本；
- 出现条件；
- 出现方式与延迟；
- 持续到点击、离开脚本、固定时长、指定事件或条件失效；
- 是否暂停后续内容等待玩家操作；
- 单次点击或允许重复点击；
- 点击后产生的事件；
- 是否调用另一段脚本；
- 是否返回调用前的脚本；
- 是否触发新的按钮或事件。

点击按钮会产生事件，事件可以引发新脚本、新事件或状态变化。部分按钮允许调用以前的可复用脚本，例如在后续流程中再次“打开手机”，完成操作后再返回现场。

### 5. 条件决定派生

条件用于描述流程中已经成立的事实。脚本、对话、按钮和事件都可以依赖条件。

条件可以来自：

- 某段前置脚本已经执行；
- 某个按钮已经点击；
- 某个事件已经发生；
- 某个事件发生达到指定次数；
- 多个事件形成特定组合。

当条件满足后，相关脚本、对话、按钮或事件自然进入可用状态。这样可以表达组合输入，例如 AI 页面根据“已上传说明书”“已发送聊天记录”“已提供当前状态”的不同组合产生不同分析结果。

## 事件动作

当前 Demo 以事件作为流程连接层，支持以下主要动作：

- **激活脚本**：让目标脚本进入可执行状态；
- **调用脚本**：暂时进入目标脚本，并保留返回位置；
- **打开侧栏**：将说明书、聊天、AI 或通用工具脚本拉起到运行区侧边栏；
- **返回脚本**：结束复用流程，回到调用前的位置；
- **显示对话**：由按钮或其他来源触发事件后，在流程继续前播放指定对话；
- **销毁对话**：由事件移除仍在持续显示的指定对话；
- **发出事件**：由一个事件继续触发另一个事件；
- **记录状态**：为后续条件提供已经发生的事实。

事件将脚本内容与流程控制分开。作者可以复用同一个“打开手机”脚本，而不必在每个剧情阶段复制一套手机界面和逻辑。

## SET 1：父亲的药

SET 1 是当前编排模型的主要验证剧本。主线是：

```text
父亲老毛病发作
  -> 去药柜拿药
  -> 阅读原始说明书
  -> 从聊天记录取得服药时间
  -> 自己判断或交给 AI 分析
  -> 实际取出药片并交给父亲
```

后台事实是：Neravil 常规首次剂量为 2 片；使用 Colvex 后 6 小时内，首次剂量不得超过 1 片。聊天记录显示父亲在 12:42 使用 Colvex，当前时间为 19:06，间隔 6 小时 24 分钟，因此正确操作是取出 2 片。

这一关没有模糊信息、AI 错误或证据冲突。它首先建立“AI 在信息完整时非常有效”的体验，为后续关卡引入信息遗漏、表达模糊、现场信息衰减和判断困难做准备。

## SET 1 的编排约束

### 顺序与复用

- S01 是典型顺序脚本，只出现一次，永不复用；
- 手机等工具脚本可以被后续脚本再次调用；
- 复用脚本需要保留返回路径；
- S09 搜索彩蛋暂不纳入主流程，待流程完善后再设计。

### 剧情自然产生选项

- 开始按钮点击后剧情才开始；
- 对话按作者设置逐条出现；
- 父亲说“老毛病犯了，帮我去药柜拿药”后，只出现“去药柜”；
- 玩家拿起蓝色盒子 Neravil 后，“说明书”按钮自然出现；
- 父亲提到中午吃过 Colvex、可能发过消息后，只出现“打开手机”；
- 打开手机后才出现“聊天”“AI”“搜索”和“返回”；
- 玩家未取药片时，不出现“给父亲配好的药”；
- 取药后可以继续取，也可以退回药片，让玩家自行控制剂量；
- 聊天页面的返回按钮文本为“返回”。

### 不使用系统提示

游戏不显示下列内容：

- “计时在此刻正式开始”；
- “准备好后继续下面选项”；
- “已读取聊天记录”；
- “请自行对照时间线判断间隔”；
- 正确与错误的系统评价；
- 本关教学目标或设计意图；
- 任何告诉玩家下一步应该点击什么的教程文字。

引导只通过剧情、台词、可操作物品和当前自然出现的按钮完成。

### 对话与右侧信息栏

- 主对话区只产生玩家与父亲的交流，以及必要的现场叙述；
- 说明书、聊天记录、AI 页面和搜索页面统一在右侧独立栏显示；
- 点击“聊天”后直接显示聊天记录，不再增加“读取聊天记录”按钮；
- 切换到聊天页面时，不出现与当前页面无关的“关闭说明书”；
- 说明书第一次打开时一次性生成完整内容，并固定在顶部；
- 说明书约 1000 字，保持接近现实药品说明书的信息密度；
- 用法用量、禁忌、注意事项和不良反应不使用差异字体颜色突出；
- 右栏滚动条保持与命令行窗口一致的视觉风格。

### AI 页面

- AI 不知道现实中未提供给它的信息；
- AI 页面按钮带条件；
- 不同输入按钮的组合触发不同的独立事件；
- 只上传说明书时，AI 提取剂量规则并指出缺少最近一次 Colvex 使用时间；
- 说明书与聊天记录等信息完整时，AI 可以得出正确结论；
- 不提供“清空 AI 分析”和“清空 AI 输入”按钮；
- 玩家始终可以不使用 AI，直接根据原始资料作出判断。

### 最终操作

最终决定不是选择题。玩家通过药板实际取出药片，再把手中的药交给父亲。正确结局只呈现剧情结果：

> 父亲服下药后，长舒了一口气，不一会脸色好看很多。

不追加判定结果、教学总结或重玩提醒。

## 当前 Demo

`narrative_editor_demo.html` 是无需构建工具和外部依赖的单文件 Demo，直接使用浏览器打开即可。

目前可以用于验证：

- 时间线脚本排序；
- 脚本关系框图与脚本间流程连线；
- 完整流程采用默认居中的自上而下分层排版，并支持滚轮缩放、拖动画布和自由移动节点；
- 手动调整的节点位置会被保留，选择模块不会重置；可通过“恢复原始排版”主动重新布局；
- 流程图会保留最后一次缩放和平移位置，事件、条件和标签视图也会保留各自的滚动位置；
- 在流程图视图点击左侧时间线脚本时，对应流程节点会平滑移动到画布中央；
- 流程节点对长标题、对话、按钮和标签进行边界裁切，不会溢出卡片；
- 当前脚本中的对话和按钮默认折叠为单行摘要，点击“展开”后编辑全部设置，拖动折叠项即可快速调整顺序；
- 主脚本时间线采用仅包含编号与标题的缩略形式，不展示脚本内容；
- 可搜索的事件库、条件库和引用位置导航；
- 脚本内容编辑；
- 对话和按钮在同一内容层级中的排序；
- 仅由事件产生、不会随脚本顺序自动播放的对话；
- 对话颜色、动效、进入脚本后的等待时间和销毁机制；
- 按钮的出现时机、持续方式和阻塞行为；
- 长对话下固定显示、独立滚动的选项栏；
- 主对话记录跨脚本持续累积，进入或退出工具页时不会消失；
- AI、聊天和说明书使用独立的可拉起侧边栏，不挤占主对话与选项栏；
- 支持手机竖屏：编辑器使用单列触控布局；游玩时打开侧栏将只显示侧栏，关闭或返回后恢复主对话；
- 侧栏脚本可配置类型、拉起事件和拉起条件；
- 条件控制；
- 事件派生；
- 脚本调用、返回与复用；
- 脚本出现事件和完成事件使用“＋、下拉框、删除”条目管理，可独立增删；
- 将当前工程直接导出为不含编辑器和调试边框的单文件游玩 HTML；
- SET 1 核心流程的运行预览。

## 数据边界与自检

编辑器在导入与运行时会归一化工程数据：等待、显示和持续时间限制在 `0` 到 `86,400,000 ms`，事件计数限制在 `0` 到 `1,000,000,000`，流程图坐标限制在 `-100,000` 到 `100,000`，缩放限制在 `0.08` 到 `3`。非有限数值、负数、未知枚举和损坏的数组项会被替换为安全默认值；循环事件链会被检测并终止，避免递归失控。

2026-09-02 对内置 SET 1 做了静态引用检查：脚本、事件和条件 ID 没有重复，脚本条件、按钮事件、事件动作目标和条件规则均能找到对应目标。JavaScript 也通过语法检查。以上是静态检查，不等于所有玩家路径的穷举测试。

当前仍有这些限制：编辑器尚未提供完整的 JSON Schema 错误报告、重复 ID 的交互式修复、撤销/重做、自动穷举路径测试和大型工程性能基准；运行状态只在本次预览会话中保留，不作为存档跨页面刷新恢复。

## 同生态位工具

本项目最接近“浏览器内可视化编排 + 事件/条件状态机 + 可直接导出单文件游玩版”的轻量组合。相邻工具各有侧重：

### GitHub / 开源

- [Twine](https://twinery.org/) 是开源的非线性故事工具，也能直接发布为 HTML；它更偏超文本段落与 Story Format 生态，本项目更强调对话/按钮生命周期、侧栏会话和显式事件条件库。
- [Yarn Spinner](https://github.com/YarnSpinnerTool/YarnSpinner) 的核心编译器在 GitHub 开源，其[功能页](https://www.yarnspinner.dev/features/)列出节点图、预览、文本表现控制、可游玩 HTML 和游戏引擎集成；它在本地化、编译器与引擎生态上更成熟，本项目则保持零构建、单文件编辑器与游玩文件。
- [ink](https://github.com/inkle/ink) 是 MIT 许可的叙事脚本语言及运行时，擅长复杂文本分支和变量逻辑；其核心工作流偏文本编写，而不是本项目这种事件、条件和 UI 生命周期的可视化配置。

### 商用

- [articy:draft](https://www.articy.com/en/articydraft/feature-list/) 是专业级叙事数据库与流程设计工具，覆盖变量、脚本、层级流程和引擎导出，能力更广但工作流和部署成本也更重。
- [Arcweave](https://arcweave.com/features) 提供在线节点编辑、实时协作、试玩及 Unity、Unreal、Godot 和 API 集成，主要优势在团队云协作与跨引擎交付。
- [ChatMapper](https://www.chatmapper.com/) 覆盖可视化分支、条件/变量、模拟和多种导出，是功能重合度很高的商用竞品；本项目的差异点是轻量单 HTML、侧栏型工具脚本、可持续/销毁的对话与按钮机制。
- [Pixel Crushers Dialogue System for Unity](https://www.pixelcrushers.com/dialogue-system/) 提供 Unity 内的完整对话运行时、UI、任务和存档集成，更适合引擎内成品开发；本项目更适合快速原型和浏览器直接交付。

后续工作将优先补充工程校验报告、撤销/重做、路径覆盖测试，以及更明确的侧栏会话分组 ID，减少依赖脚本命名约定。
