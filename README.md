# Interactive Script Orchestrator

一个面向交互叙事游戏的可视化脚本编排器 Demo。

项目当前聚焦于四个核心概念：**脚本、按钮、事件、条件**。编辑器不试图替作者自动创作剧情，而是让作者把已经设计好的对话、顺序和交互关系清楚地编排出来，并直接预览玩家实际会经历的流程。

## 核心模型

### 1. 脚本是基本载体

脚本是时间线上的基本节点，也是整个编辑器的主体。作者可以：

- 在时间线上新增脚本；
- 拖动脚本改变作者规定的执行顺序；
- 自定义每段脚本的对话内容；
- 将脚本设置为只执行一次或允许复用；
- 通过事件调用其他脚本；
- 在复用脚本后返回此前流程，从而形成闭环。

这里的“时间线”不是现实时间刻度，而是作者规定的主要脚本进行顺序。运行时可以因为按钮、条件和事件进入支线，也可以调用可复用脚本后回到原流程。

### 2. 脚本承载对话

每个脚本可以包含一条或多条对话。每条对话由作者明确设计，并可以设置：

- 说话者或叙述客体；
- 代表该客体的文字颜色；
- 文字出现动效；
- 完全显示所需时间；
- 逐字出现速度；
- 特殊文本类型，例如统一使用白色字体的药品名称。

动效应以可复用的类存在。例如“砰”可以使用颤动效果，后续作者只需给其他对话指定同一动效类，而不需要重新实现动画。

对话区只呈现角色交流和必要的现场叙述，不承担教程提示、操作提醒或系统评价。

### 3. 对话可以关联条件和事件

一条对话可以承载两个独立属性：

- **出现条件**：只有条件满足时，对话才会出现；
- **产生事件**：对话出现后触发指定事件。

例如，某句对话出现后产生“药柜按钮可用”事件，界面才显示“去药柜”按钮。玩家感受到的是剧情自然推进，而不是系统告诉玩家下一步该做什么。

### 4. 按钮附着于脚本

按钮不是独立漂浮的菜单，而是当前脚本在特定状态下提供给玩家的行动。按钮可以设置：

- 显示文本；
- 出现条件；
- 点击后产生的事件；
- 是否调用另一段脚本；
- 是否返回调用前的脚本；
- 是否触发新的按钮或事件。

点击按钮会产生事件，事件可以引发新脚本、新事件或状态变化。部分按钮允许调用以前的可复用脚本，例如在后续流程中再次“打开手机”，完成操作后再返回现场。

### 5. 条件决定派生

条件用于描述流程中已经成立的事实。脚本、对话、按钮和事件都可以依赖条件。

条件可以来自：

- 某段前置脚本已经执行；
- 某个按钮已经点击；
- 某个事件已经发生；
- 某个事件发生达到指定次数；
- 多个事件形成特定组合。

当条件满足后，相关脚本、对话、按钮或事件自然进入可用状态。这样可以表达组合输入，例如 AI 页面根据“已上传说明书”“已发送聊天记录”“已提供当前状态”的不同组合产生不同分析结果。

## 事件动作

当前 Demo 以事件作为流程连接层，支持以下主要动作：

- **激活脚本**：让目标脚本进入可执行状态；
- **调用脚本**：暂时进入目标脚本，并保留返回位置；
- **返回脚本**：结束复用流程，回到调用前的位置；
- **发出事件**：由一个事件继续触发另一个事件；
- **记录状态**：为后续条件提供已经发生的事实。

事件将脚本内容与流程控制分开。作者可以复用同一个“打开手机”脚本，而不必在每个剧情阶段复制一套手机界面和逻辑。

## SET 1：父亲的药

SET 1 是当前编排模型的主要验证剧本。主线是：

```text
父亲老毛病发作
  -> 去药柜拿药
  -> 阅读原始说明书
  -> 从聊天记录取得服药时间
  -> 自己判断或交给 AI 分析
  -> 实际取出药片并交给父亲
```

后台事实是：Neravil 常规首次剂量为 2 片；使用 Colvex 后 6 小时内，首次剂量不得超过 1 片。聊天记录显示父亲在 12:42 使用 Colvex，当前时间为 19:06，间隔 6 小时 24 分钟，因此正确操作是取出 2 片。

这一关没有模糊信息、AI 错误或证据冲突。它首先建立“AI 在信息完整时非常有效”的体验，为后续关卡引入信息遗漏、表达模糊、现场信息衰减和判断困难做准备。

## SET 1 的编排约束

### 顺序与复用

- S01 是典型顺序脚本，只出现一次，永不复用；
- 手机等工具脚本可以被后续脚本再次调用；
- 复用脚本需要保留返回路径；
- S09 搜索彩蛋暂不纳入主流程，待流程完善后再设计。

### 剧情自然产生选项

- 开始按钮点击后剧情才开始；
- 对话按作者设置逐条出现；
- 父亲说“老毛病犯了，帮我去药柜拿药”后，只出现“去药柜”；
- 玩家拿起蓝色盒子 Neravil 后，“说明书”按钮自然出现；
- 父亲提到中午吃过 Colvex、可能发过消息后，只出现“打开手机”；
- 打开手机后才出现“聊天”“AI”“搜索”和“返回”；
- 玩家未取药片时，不出现“给父亲配好的药”；
- 取药后可以继续取，也可以退回药片，让玩家自行控制剂量；
- 聊天页面的返回按钮文本为“返回”。

### 不使用系统提示

游戏不显示下列内容：

- “计时在此刻正式开始”；
- “准备好后继续下面选项”；
- “已读取聊天记录”；
- “请自行对照时间线判断间隔”；
- 正确与错误的系统评价；
- 本关教学目标或设计意图；
- 任何告诉玩家下一步应该点击什么的教程文字。

引导只通过剧情、台词、可操作物品和当前自然出现的按钮完成。

### 对话与右侧信息栏

- 主对话区只产生玩家与父亲的交流，以及必要的现场叙述；
- 说明书、聊天记录、AI 页面和搜索页面统一在右侧独立栏显示；
- 点击“聊天”后直接显示聊天记录，不再增加“读取聊天记录”按钮；
- 切换到聊天页面时，不出现与当前页面无关的“关闭说明书”；
- 说明书第一次打开时一次性生成完整内容，并固定在顶部；
- 说明书约 1000 字，保持接近现实药品说明书的信息密度；
- 用法用量、禁忌、注意事项和不良反应不使用差异字体颜色突出；
- 右栏滚动条保持与命令行窗口一致的视觉风格。

### AI 页面

- AI 不知道现实中未提供给它的信息；
- AI 页面按钮带条件；
- 不同输入按钮的组合触发不同的独立事件；
- 只上传说明书时，AI 提取剂量规则并指出缺少最近一次 Colvex 使用时间；
- 说明书与聊天记录等信息完整时，AI 可以得出正确结论；
- 不提供“清空 AI 分析”和“清空 AI 输入”按钮；
- 玩家始终可以不使用 AI，直接根据原始资料作出判断。

### 最终操作

最终决定不是选择题。玩家通过药板实际取出药片，再把手中的药交给父亲。正确结局只呈现剧情结果：

> 父亲服下药后，长舒了一口气，不一会脸色好看很多。

不追加判定结果、教学总结或重玩提醒。

## 当前 Demo

`narrative_editor_demo.html` 是无需构建工具和外部依赖的单文件 Demo，直接使用浏览器打开即可。

目前可以用于验证：

- 时间线脚本排序；
- 脚本内容编辑；
- 对话颜色、动效和显示时间；
- 按钮与脚本的附着关系；
- 条件控制；
- 事件派生；
- 脚本调用、返回与复用；
- SET 1 核心流程的运行预览。

后续工作将优先继续完善各个选项的派生、脚本的自由进程，以及按钮、事件、条件和可复用脚本之间的联系。
